## Perfis (roles)

Roles são **dados** (não hardcoded), gerenciados em **Perfis** (`/perfis`).

Perfis típicos (seed Flyway / provisionamento):

| Perfil | Escopo | Exemplos de permissões |
|--------|--------|------------------------|
| Super Admin | Global (`school_id` nulo) | Todas |
| School Admin | Uma escola | Catálogo + usuários da escola |
| PROFESSOR | Escola | `books.view`, `books.toggle_status`, `sites.view`, `sites.toggle_status` |

## Modelo de permissões

Formato: `recurso.acao` — exemplos:

- `books.view|create|update|delete|toggle_status`
- `users.view|create|update|block|delete`
- `sites.view|create|update|delete|toggle_status`
- `sites.comments.view|moderate`
- `schools.*`, `team.*`, `roles.*`, `acervos.*`, `reports.view`

**Fonte de verdade:** backend (`*Policy` + anotações de segurança). O frontend só esconde UI (`PermissionGate` / `usePermission`).

## Contexto de escola

- Header do painel: seletor de escola (quando aplicável).
- Header HTTP: `X-School-Context`.
- Escrita em catálogo/usuários respeita tenant da escola ativa.
