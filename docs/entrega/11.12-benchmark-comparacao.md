# 11.12 — Referências modelo, benchmark e comparação prática

## Modelo de referência (antes)

**Stack legado:** PHP procedural + MySQL + painel `adm-libares` + APIs `api.php` / `api_sites.php` / `user_*.php` + apps Flutter.

Características:
- Autenticação admin fraca (papel único).
- Sem isolamento real por escola no painel.
- UI fragmentada (`manage_*.php`, `add_*.php`).
- Lógica de negócio misturada com apresentação.
- Deploy acoplado a Apache/PHP na hospedagem.

## Modelo alvo (depois)

**Stack nova:** Kotlin/Spring Boot + React/Vite + MySQL legado (compat) + Docker/VPS + espelho PHP para Flutter.

Características:
- JWT + RBAC granular + multi-tenant.
- UI única Berry com padrões de listagem/FormModal.
- Domínio modular (`catalog`, `site`, `reader`, `users`, …).
- Contratos OpenAPI (Swagger).
- Deploy reproduzível.

## Benchmark / comparação prática

| Dimensão | PHP legado | Solução atual | Ganho prático |
|----------|------------|---------------|---------------|
| Segurança painel | Admin único | RBAC + Policies | Menor risco de acesso indevido |
| Multi-escola | Frágil / inexistente | `school_id` + contexto | SaaS escolar viável |
| UX operador | Telas PHP distintas | Shell único + modais | Treinamento mais rápido |
| Manutenção | Scripts PHP espalhados | Módulos + specs | Onboarding e IA assistida |
| App Flutter | Host PHP | Host Kotlin (mesmo path) | Cutover sem reescrever app |
| Observabilidade | Logs Apache | Actuator + audit + Docker logs | Diagnóstico mais rápido |
| Evolução schema | Alterações manuais | Flyway versionado | Rollback/controle |
| Documentação | Escassa | Specs + planos + roteiro 11.x | Aceite e auditoria de entrega |
| Site + ebook | Dois mundos no PHP | Dois módulos, um painel | Operação unificada |
| Senha leitor | Plaintext em forgot | Sem senha em claro | Conformidade melhor |

## Referências de mercado / padrões usados

- **Spring Security** + JWT (API stateless)
- **RBAC** resource.action (comum em painéis B2B)
- **CQRS leve** (use cases) sem over-engineering
- **BFF não aplicado** — React consome API direta (same-origin via Nginx)
- **Strangler Fig** — espelho PHP mantém Flutter enquanto o núcleo migra
- **Design system** inspirado em templates admin (Berry) adaptado ao produto

## Comparação com alternativas consideradas

| Alternativa | Por que não (ou adiada) |
|-------------|-------------------------|
| Reescrever Flutter já em REST `/api/v1` | Custo alto; espelho PHP desbloqueia cutover |
| Migrar produção para Postgres/`core` na mesma onda | Risco; mantido como gancho paralelo |
| Manter admin em PHP e só API nova | Não elimina dívida do painel |
| Monólito Node full-stack | Time alinhado a Kotlin + React já existentes |

## Conclusão do benchmark

A migração prova o padrão **strangler + multi-tenant + RBAC + UI unificada** sobre base legada, com caminho claro para desligar PHP após homologação do app — sem big-bang de dados nem reescrita do Flutter no caminho crítico.
