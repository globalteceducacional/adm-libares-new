# 11.6 — Backend, APIs padronizadas e segurança

## Stack backend

- **Kotlin** + **Spring Boot 3**
- Persistência: JPA (admin) + JDBC (queries espelho leitor)
- Migrações: **Flyway**
- Auth painel: **JWT** (Bearer)
- Docs: **springdoc OpenAPI** → `/swagger-ui.html`, `/v3/api-docs`

## Superfícies de API

### A) Admin REST (autenticado)

Prefixo: `/api/v1/`

| Área | Exemplos |
|------|----------|
| Auth | `POST /auth/login`, `GET /auth/me` |
| Books | CRUD + upload cover/file + toggle status |
| Users | CRUD parcial, `PUT /{id}` perfil, status, acervo |
| Sites | CRUD + uploads + `PATCH /{id}/status` |
| Schools / Team / Roles | CRUD FormModal |
| Audit | `GET /audit/overview` |
| Dashboard | endpoints de KPIs |

**Padrão de erro:** envelope JSON do backend (400/401/403/404).  
**Escrita:** Policies (`BookPolicy`, `UserPolicy`, `SitePolicy`, …) + tenant.

### B) Leitor espelho PHP (público)

| Rota | Envelope |
|------|----------|
| `/api.php?method_name=...` | `EBOOK_APP` |
| `/user_login_api.php` (e register/profile/forgot) | legado |
| `/api_sites.php?method_name=...` | `Galileu` |

Security: `permitAll` nessas rotas (paridade PHP). Sem JWT admin.

### C) Assets

`GET /legacy/assets/**` — público; sem repassar Authorization no proxy de imagens.

## Segurança

| Controle | Implementação |
|----------|----------------|
| Autenticação painel | JWT + secret configurável (`JWT_SECRET`) |
| Autorização | RBAC granular no servidor |
| Tenant | `school_id` + header `X-School-Context` |
| Senhas | BCrypt; upgrade-on-login no leitor |
| CORS | `CORS_ALLOWED_ORIGIN_PATTERNS` |
| Upload | Validação de tipo/tamanho no storage legado |
| Swagger | Exige JWT admin |
| Health | `/actuator/health` público (monitoramento) |

## Padronização

- DTOs com Bean Validation (`@NotBlank`, `@Email`, `@Size`).
- Use cases por operação (`Create*`, `Update*`, `Delete*`).
- Controllers finos; lógica em `application/`.
- ITs MockMvc por módulo (`*IT.kt`).

- `/legacy/assets/` → backend
