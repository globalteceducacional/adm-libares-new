# 11.4 — UX, telas e protótipos funcionais

## Direção visual

- Design system inspirado em **Berry Admin** (Material-like).
- Tokens CSS, tipografia consistente, cards elevados, motion com Framer Motion.
- Spec de redesign: `docs/superpowers/specs/2026-07-03-berry-frontend-redesign.md`.

## Padrão de telas de listagem (protótipo funcional reutilizável)

Cada módulo de CRUD segue o mesmo shell:

1. **Breadcrumbs** + **PageHeroStrip** (ícone, título, descrição, CTA “Novo”)
2. **ListingMiniStats** (KPIs da lista)
3. **AdminListingSection**: busca (`q`), filtro status, tabela/cards mobile
4. **FormModal** para create/edit (padrão Acervos/Escolas/Sites/Usuários)
5. **DetailModal** quando há ações secundárias (acervo do usuário, moderação, etc.)
6. **ConfirmDialog** para exclusões
7. Feedback: toast (`useAdminMutation`) + alertas de formulário

## Evoluções UX recentes

| Entrega | Spec / efeito |
|---------|----------------|
| Dashboard enxuto | Layout C — menos ruído, alertas de catálogo |
| Auditoria Berry | Shell + KPIs + refresh, sem filtros avançados nesta versão |
| FormModals Sistema | Escolas / Equipe / Perfis sem BerryFormPanel inline |
| Usuários | Create+edit perfil em modal; Editar na linha e no detalhe |
| Fase a11y | Labels/erros de campo em formulários de catálogo |
| Fase 8 | Mutações via `useAdminMutation` (menos boilerplate, toasts consistentes) |

## Acessibilidade e responsivo

- Formulários com `aria-invalid` / mensagens de erro após submit.
- Tabelas com fallback **card mobile** (`renderMobileCard`).
- Botões de ação com `aria-label` em exclusões críticas.
