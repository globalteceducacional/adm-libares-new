## Versionamento

- Git Flow simplificado: features em branch → merge/PR → `main` → deploy VPS (`reset --hard origin/main`).
- Mensagens: Conventional Commits (`feat`, `fix`, `docs`, `refactor`, `chore`).
- Specs e planos **versionados no mesmo repo** (`docs/superpowers/`), datados `YYYY-MM-DD-…`.
- Schema: Flyway `V1`…`Vn` (não editar migrações já aplicadas em produção; criar nova versão).

## Uso de IA no desenvolvimento

Ferramenta: **Cursor** (agentes + skills Superpowers).

### Processo adotado

1. **Brainstorm / Spec** — design aprovado antes de codar (`docs/superpowers/specs/`).
2. **Writing plans** — plano com tasks checkbox (`docs/superpowers/plans/`).
3. **Subagent-Driven Development** — implementer → review de spec → review de qualidade por task.
4. **Finishing branch** — merge local / push / PR conforme escolha.
5. **Verificação** — `tsc`, `compileKotlin`, ITs quando DB disponível.

### Benefícios observados

- Consistência entre módulos (FormModal, `useAdminMutation`, Policies).
- Rastreabilidade: cada feature tem spec + plano + commits.
- Menos regressão de padrões UX/API.

### Controles humanos

- Aprovação de escopo antes de implementar.
- Review de commits sensíveis (deploy, segurança).
- Smoke e homologação manual (Flutter, VPS).
- Segredos nunca commitados (`.env`, senhas).
