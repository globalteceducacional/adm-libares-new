# 11.5 — Banco de dados, entidades e rastreabilidade

## Estratégia

- **Produção atual:** `APP_DATA_MODE=legacy` — MySQL com tabelas PHP (`tbl_*`, `Sites`, etc.).
- **Evolução:** schema `adm_libare_core` (`app_*`, `catalog_*`, …) via scripts em `scripts/migration/` e Flyway V2/V3 — **não** é o modo default da VPS.
- Evolução incremental: Flyway `V1`…`V22` aplica colunas/seeds sem reescrever o dump.

Documentação base: `docs/database-redesign-and-migration.md`.

## Rastreabilidade

| Mecanismo | Uso |
|-----------|-----|
| Flyway `flyway_schema_history` | Versão de schema aplicada |
| `AuditSessionContext` | Define ator (`@app_user_id`) em escritas |
| Triggers / views audit (modo core) | `vw_audit_*`, API `/api/v1/audit/overview` |
| Tela Auditoria | `/auditoria` — KPIs e blocos de overview |
| Logs Docker | `docker compose logs backend` |
| Git | Histórico de features + specs datadas |
